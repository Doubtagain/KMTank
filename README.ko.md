# KMTank

diep.io 계열의 실시간 브라우저 탱크 아레나입니다. 서버 권위(authoritative) 방식으로
동작하며, 구글 로그인과 랭크(티어) 시스템을 갖추고 있습니다.

English: [README.md](README.md)

```
도형을 파밍하고 → 레벨을 올리고 → 빌드를 고르고 → 끝까지 살아남기.
```

## 특징

- **서버 권위 시뮬레이션.** 위치, 피격, 경험치까지 모든 판정이 서버에서 이뤄집니다.
  클라이언트는 9바이트짜리 입력 프레임만 보내고 바이너리 스냅샷을 받습니다.
- **20 Hz 틱 + 보간 렌더링.** 클라이언트는 110ms 과거를 그리며 스냅샷 사이를 보간하고,
  내 탱크만은 같은 이동 모델을 클라에서 예측해 키 입력이 즉시 반응합니다.
- **4단계 26종 탱크 클래스.** 15레벨에 Twin / Sniper / Machine Gun / Flank Guard로
  분기하고, 30레벨과 45레벨에서 다시 갈라집니다. 클래스는 곧 포신(barrel) 목록이라
  시뮬레이션 코드에는 클래스별 분기가 없습니다.
- **8종 스탯 업그레이드**, 각 7포인트까지.
- **랭크 래더.** 구글 로그인 → 다인전 Elo 기반 MMR → 배치고사 5판 → Bronze III부터
  Challenger까지 8티어. 시즌제를 지원합니다.
- **AI 봇.** 사람이 없어도 아레나가 비지 않습니다. 봇은 플레이어와 완전히 같은
  입력 구조를 쓰며, 레벨 상한이 있어 신규 플레이어를 벽으로 막지 않습니다.

## 기술 스택

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 공용 | TypeScript (런타임 의존성 0) | 상수·탱크 트리·레이팅 계산·와이어 코덱을 한 번만 컴파일해 양쪽에서 import → 클라/서버 규칙이 어긋날 수 없음 |
| 서버 | Node 22, `ws`, `node:http` | 고정 타임스텝 루프 하나가 모든 방을 구동. 라우트 6개에 프레임워크는 과함 |
| DB | Postgres (`pg`) | `DATABASE_URL`이 없으면 인메모리로 폴백 → `npm run dev`에 설정이 전혀 필요 없음 |
| 인증 | Google Identity Services → `google-auth-library` → 자체 JWT | ID 토큰을 서버에서 우리 client id로 검증. 브라우저는 장기 구글 자격증명을 들고 있지 않음 |
| 클라이언트 | Vite + TypeScript + Canvas 2D | gzip 15 KB, 프레임워크 없음 |

## 빠른 시작

```bash
npm install
npm run dev
```

공용 패키지를 빌드하고 서버(`:8080`)와 클라이언트(`:5173`)를 함께 띄웁니다.
http://localhost:5173 에서 **Play Casual**을 누르면 바로 플레이됩니다 —
DB도, 구글 client id도, 어떤 설정도 필요 없습니다.

로컬에서 랭크를 테스트하려면 `.env`에 `ALLOW_DEV_LOGIN=1`을 넣고
`POST /api/auth/dev`를 쓰거나(아래 [테스트](#테스트) 참고), 실제
`GOOGLE_CLIENT_ID`를 설정하세요.

### 조작

| 입력 | 동작 |
| --- | --- |
| `WASD` / 방향키 | 이동 |
| 마우스 | 조준 |
| 클릭 / `Space` | 발사 |
| `E` | 자동 발사 토글 |
| `C` | 자동 회전 토글 |
| `1`~`8` | 스탯 포인트 투자 |

터치도 지원합니다. 화면 왼쪽 절반을 드래그하면 이동, 오른쪽 절반은 조준·발사입니다.

## 설정

모든 항목은 [`.env.example`](.env.example)에 있습니다. 중요한 것만:

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `JWT_SECRET` | 개발용 임시값 | **운영에서는 반드시 변경.** 세션 토큰 서명 키 |
| `GOOGLE_CLIENT_ID` | 없음 | 없으면 랭크가 비활성화되고 메뉴에 안내가 뜸 |
| `DATABASE_URL` | 없음 | 없으면 랭크가 메모리에만 남아 재시작 시 초기화 |
| `CORS_ORIGINS` | `*` | 운영에서는 클라이언트 origin으로 제한 |
| `BOT_TARGET` | `8` | 캐주얼 방당 AI 탱크 수 |
| `RANKED_MATCH_SECONDS` | `480` | 랭크 매치 길이 |
| `RANKED_QUEUE_GRACE` | `30` | 인원이 덜 찬 대기열이 기다리는 시간 |
| `VITE_SERVER_URL` | 로컬 | 클라이언트 빌드 시점에 박히는 서버 주소 |

## 배포 (전부 무료 티어)

단계별 안내(한국어, Cloudflare Pages + Railway + Supabase 기준)는 [docs/DEPLOY.ko.md](docs/DEPLOY.ko.md)에 있습니다. 영문/대안 서비스 포함 버전은 [docs/DEPLOY.md](docs/DEPLOY.md).

- **클라이언트** → Cloudflare Pages
  (빌드 `npm run build -w @kmtank/shared && npm run build -w @kmtank/client`,
  출력 `packages/client/dist`). Vercel도 `vercel.json`으로 그대로 동작합니다.
- **서버** → Railway(`railway.json`, 월 $5 Hobby), Render 무료 플랜(`render.yaml`), Fly.io(`fly.toml`) 중 택일.
  전부 루트 `Dockerfile`을 빌드합니다.
- **DB** → Neon 또는 Supabase 무료 Postgres. 스키마는 서버 부팅 시 자동 적용됩니다.

트레이드오프는 하나입니다: Render 무료 인스턴스는 약 15분간 트래픽이 없으면 잠들어
첫 접속자가 30~60초를 기다립니다. Railway와 Fly.io는 상시 가동이라 콜드 스타트가 없는 대신
소액 유료입니다.

## 디렉터리 구조

```
packages/
  shared/   상수, 탱크 트리, 스탯 곡선, 레이팅 계산, 바이너리 코덱
  server/   시뮬레이션, 매치메이킹, 인증, 영속화, 웹소켓 게이트웨이
  client/   캔버스 렌더러, 예측, HUD, 메뉴
tools/      스모크 테스트 · 랭크 시뮬레이션용 헤드리스 클라이언트
docs/       배포 가이드
```

## 테스트

```bash
# 캐주얼 접속 → 이동 → 스냅샷 디코딩과 경험치 획득 검증
node tools/smoke-client.mjs

# 스크립트 플레이어 4명으로 랭크 매치 한 판을 끝까지 돌리고 MMR 정산 출력
# (서버를 ALLOW_DEV_LOGIN=1 로 띄워야 함)
node tools/ranked-sim.mjs 4
```

`npm run typecheck`으로 세 패키지를 모두 타입 검사합니다. CI는 푸시마다
타입 검사 + 빌드 + 위 스모크 테스트 + Docker 빌드를 돌립니다.

## 설계 메모

**왜 바이너리 스냅샷인가?** 시야 안에 보통 200개 정도의 엔티티가 있습니다.
JSON이면 스냅샷당 약 30 KB지만, 위치·각도를 u16으로 양자화하면 실측 1.1 KB입니다.
20 Hz 기준으로 플레이어당 600 KB/s와 22 KB/s의 차이입니다.

**왜 롤백 예측을 안 쓰나?** 완전한 예측·재조정을 하려면 충돌 모델 전체를 브라우저로
옮기고 입력을 재생해야 합니다. 대신 체감 지연을 대부분 차지하는 "내 탱크의 이동
속도"만 예측하고, 스냅샷마다 서버 위치로 부드럽게 수렴시킵니다. 충돌과 넉백은
보정값으로 들어옵니다. 복잡도의 일부로 이득의 대부분을 가져오는 선택입니다.

**왜 클래스가 포신 목록인가?** Twin과 Octo Tank의 차이는 전부 포신 배치, 재장전 위상,
탄환 배수로 표현됩니다. 선언적으로 두면 클래스 추가가 데이터 변경이 되고,
클라이언트는 존재조차 모르는 클래스도 그리고 미리보기할 수 있습니다.

**왜 나간 플레이어도 레이팅에 반영하나?** 나갈 때 점수 그대로 순위에 넣습니다.
그러지 않으면 지고 있을 때 최적의 플레이가 "탭 닫기"가 되기 때문입니다.
